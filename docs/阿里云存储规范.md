# 阿里云存储使用规范

> 服务器: 8.138.235.183（阿里云广州）
> 适用: 所有团队成员

---

## 一、磁盘结构

| 磁盘 | 挂载点 | 容量 | 用途 | 建议 |
|------|--------|------|------|------|
| 系统盘 `/dev/vda1` | `/` | **40GB** | 操作系统、系统软件 | **仅放系统文件** |
| 数据盘 `/dev/vdb1` | `/mnt/data` | **~1000GB** | 业务数据 | **所有业务数据放此处** |

### 当前状态（2026-05-23）

| 路径 | 目前所在 | 大小 | 应放位置 |
|------|---------|------|---------|
| `/www/wwwroot/` (WordPress站点) | ❌ 系统盘 | ~13G | **数据盘** |
| `/www/server/data` (MySQL) | ❌ 系统盘 | ~1.5G | **数据盘** |
| `/root/` (个人文件) | ❌ 系统盘 | ~3.1G | **数据盘** |
| `/mnt/data/` | ✅ 数据盘 | 147G/985G | — |

**⚠️ 系统盘40GB一旦写满，服务器会崩溃（MySQL写不了、SSH登录不了、网站打不开），所以必须严格控制系统盘使用。**

## 二、存储规范

### 2.1 什么可以放系统盘

| 可以放 | 不可以放 |
|--------|---------|
| 操作系统文件 | ❌ WordPress站点文件 |
| yum/软件包 | ❌ MySQL数据库文件 |
| 系统日志（适量） | ❌ 备份文件、压缩包 |
| /etc 配置 | ❌ 项目代码 |
| 临时编译产物（用完即删） | ❌ 个人文件 |

### 2.2 数据盘目录规划（/mnt/data）

```
/mnt/data/
├── www/              # WordPress站点文件（软链接到/www）
│   ├── 12fz.com/
│   ├── dev.12fz.com/
│   ├── goxeou.12fz.com/
│   └── ...
├── mysql/            # MySQL数据库（软链接）
├── backup/           # 所有备份文件
│   ├── database/     # 数据库备份
│   ├── website/      # 站点文件备份
│   └── daily/        # 每日增量
├── logs/             # 滚动归档日志
├── projects/         # 项目代码
│   └── 12fz-dev/     # GitHub仓库
└── temp/             # 临时文件（定期清理）
```

### 2.3 迁移计划

**\#1 WordPress站点 → 数据盘**
```bash
# 停止nginx和php
systemctl stop nginx php-fpm

# 移动站点文件
mv /www/wwwroot /mnt/data/www

# 创建软链接
ln -sf /mnt/data/www /www/wwwroot

# 重启服务
systemctl start nginx php-fpm
```

**\#2 MySQL数据库 → 数据盘**
```bash
# 停止MySQL
systemctl stop mysqld

# 移动数据目录
mv /www/server/data /mnt/data/mysql

# 创建软链接
ln -sf /mnt/data/mysql /www/server/data

# 重启MySQL
systemctl start mysqld
```

**\#3 个人文件**
```bash
# /root下的大文件迁移到数据盘
mv /root/*.tar.gz /mnt/data/backup/
mv /root/*.log /mnt/data/logs/
```

## 三、清理规则

### 3.1 定期清理项

| 类型 | 保留时长 | 命令 |
|------|---------|------|
| 系统日志 | 7天 | `journalctl --vacuum-time=7d` |
| 压缩包安装包 | 安装完立即删 | `rm -f *.tar.gz *.zip` |
| 数据库备份 | 保留最近3份 | 脚本自动清理 |
| /tmp 文件 | 重启自动清 | 不存重要文件 |
| nps日志 | 30天滚动 | logrotate管理 |

### 3.2 磁盘告警阈值

| 级别 | 系统盘使用率 | 操作 |
|------|------------|------|
| 🟢 正常 | < 60% | 无需处理 |
| 🟡 注意 | 60% ~ 80% | 检查并清理 |
| 🟠 警告 | 80% ~ 90% | 立即清理 |
| 🔴 危险 | > 90% | **立即处理，可能宕机** |

### 3.3 监控命令

```bash
# 检查磁盘使用
df -h

# 找大文件（系统盘）
du -sh /* 2>/dev/null | sort -rh | head -20

# 找大于100MB的文件
find / -type f -size +100M 2>/dev/null | head -20

# 检查inode使用（小文件过多也会占满）
df -i
```

## 四、备份策略

### 4.1 数据库备份
```bash
# 每日凌晨3点自动备份，保留7天
mysqldump --all-databases | gzip > /mnt/data/backup/database/db_$(date +%Y%m%d).sql.gz
```

### 4.2 站点文件备份
```bash
# 每周备份到数据盘
tar czf /mnt/data/backup/website/12fz_$(date +%Y%m%d).tar.gz /mnt/data/www/
```

### 4.3 备份保留
- 数据库备份：保留最近7天
- 站点文件备份：保留最近4周
- 每季度做一次全量冷备份

## 五、团队规范

### 5.1 上传文件
- 通过WordPress后台上传 → 自动存在 `/mnt/data/www/`（站点迁移后）
- FTP上传 → 传到 `/mnt/data/www/xxx/`
- **禁止** 直接上传大文件到系统盘

### 5.2 代码仓库
- GitHub仓库 clone 到 `/mnt/data/projects/`
- 不要 clone 到 `/root/` 或 `/home/`

### 5.3 临时文件
- 临时下载的文件用完后立即删除
- 大文件处理完确认不需要后立即清理
- 下载到 `/tmp/` 而不是 `/root/`

### 5.4 发现问题
- 发现系统盘使用率超过70% → 群里@chaogu-ai
- 发现未知大文件 → 确认后删除或迁移
- 任何存储相关变更 → 更新本文档
