# 备份与恢复流程

> 全量规范见 `docs/协作规则.md` 第八节

## 操作前必备备份

| 操作内容 | 备份方式 |
|---------|---------|
| 改配置文件 | `cp xxx.conf xxx.conf.bak.$(date +%Y%m%d_%H%M%S)` |
| 改数据库 | 先 `mysqldump` 全量备份 |
| 改代码 | 走Git分支，不直接改线上 |
| 改NPS隧道 | 先API导出全量清单 |
| 大批量更改 | 先改1条测试，验证后再批量 |

## 自动备份

| 类型 | 频率 | 保留期 | 目标 |
|------|------|--------|------|
| 快速快照 | 每小时 | 24小时 | 关键配置文件 |
| 每日全量 | 每天00:00 BJT | 7天 | 配置文件+数据库 |

备份路径: `/mnt/data/12fz/backup/config/`

## 恢复优先级

1. 🔴 从备份恢复（`.bak` 或 `/mnt/data/12fz/backup/`）
2. 🟡 备份丢失但API可用 → 用API重建（如NPS）
3. ⚪ 都没有 → Web后台手动重建

## 毁损检测

cron每5分钟检查配置文件大小，低于阈值 → 群内报警。
